# System.IO.Abstractions' FileSystem, and the wrappers it is assembled from, pass every call
# straight to System.IO: they are the whole filesystem behind an interface. Only construction
# is reported. Code that takes an IFileSystem reaches whatever it was handed, which is the
# point of taking one, and a DirFileSystem hands it a Dir. The same holds for Testably's
# RealFileSystem. Each entry names its type by metadata name, so the list applies whether or
# not a project references either library, and reports nothing in one that does not.
# FileVersionInfoWrapper is left out: it wraps version data that has already been read, and
# reaches nothing itself.
M:System.IO.Abstractions.FileSystem.#ctor;The whole filesystem behind IFileSystem, reached by path. Construct a Cap.IO.Abstractions.DirFileSystem over a Cap.Std.Dir instead.
M:System.IO.Abstractions.FileWrapper.#ctor;Calls System.IO.File, against the whole filesystem. Take IFileSystem.File from a Cap.IO.Abstractions.DirFileSystem over a Cap.Std.Dir instead.
M:System.IO.Abstractions.DirectoryWrapper.#ctor;Calls System.IO.Directory, against the whole filesystem. Take IFileSystem.Directory from a Cap.IO.Abstractions.DirFileSystem over a Cap.Std.Dir instead.
M:System.IO.Abstractions.FileInfoWrapper.#ctor;Wraps a FileInfo, which names a file by path against the whole filesystem. Use IFileSystem.FileInfo from a Cap.IO.Abstractions.DirFileSystem over a Cap.Std.Dir instead.
M:System.IO.Abstractions.DirectoryInfoWrapper.#ctor;Wraps a DirectoryInfo, which names a directory by path against the whole filesystem. Use IFileSystem.DirectoryInfo from a Cap.IO.Abstractions.DirFileSystem over a Cap.Std.Dir instead.
M:System.IO.Abstractions.DriveInfoWrapper.#ctor;Wraps a DriveInfo, one of the machine's volumes, which is not something a capability grants.
